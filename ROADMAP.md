# ATOMIC Studio — Roadmap: "the IDE you live in"

Goal (Mohamed, 2026-07-06): turn ATOMIC Studio into a real editor he *works in instead of the Claude
terminal* — left-side file/folder explorer, tabbed live previews (web **and** app, incl. built-in phone
simulators), support for more frameworks, and deliberately solve the things people hate about competitors.

---

## 0. Direction set 2026-08-06 (Mohamed) — three positions that override earlier assumptions

**A · One core, two personalities — Builder Mode and Developer Mode. BUILT 2026-08-09.**
The "two audiences, one UI" premise is rejected. A developer wants speed, shortcuts, keyboard, git and
debugging; a non-coder wants chat, preview, deploy and no code. Those are close to two products, and a
single interface serves neither. The core (agent, index, **memory**, safety, preview) is identical in
both; only the surface differs.
`src/shared/mode.ts` is the one table that says what each mode shows — read by the renderer AND by the
main-process menu, so a hidden surface has no menu item, palette action or shortcut left pointing at it.
Builder Mode drops the file tree, editor tabs, terminal, search, extensions, git and the engineering
half of Insight; keeps chat, preview, undo, health/history, and plain-English wording. **It hides, it
never closes**: open files (unsaved typing included) come back exactly as they were on the way back to
Developer Mode. The choice lives in the main process (`<userData>/mode.json`, `STUDIO_MODE` overrides
for a run), switches from a status-bar chip or Settings ▸ Mode, and is offered once — as a dismissible
line at the top of the workspace, never a dialog. **Still to do:** deploy is not yet a first-class
Builder action, and the two modes share one wording pass rather than two written voices.

**B · "AI Build Receipt" — BUILT 2026-08-09.** Eight of the ten fields ship: files changed, git-style line counts, **byte delta per file and total**, checks run/passed, duration, tokens for that run, read-first confidence, screenshot, and a one-click rollback id. **Performance delta and bundle delta are still not built** — both need a build-metrics probe (run the project's build, diff `dist/` size, run a benchmark), which is minutes per run and therefore opt-in work, not a default. Until then they are omitted rather than shown as zero.

*(original entry)* **"AI Build Receipt" is the signature feature, and it is bigger than what exists today.**
The receipt shipped on 2026-08-06 covers the summary + a screenshot of the change working. The full
feature is a per-run receipt carrying:
`files changed · tests passed · preview screenshot · performance delta · bundle delta · git diff ·
rollback id · time spent · tokens spent · confidence`.
Nothing else on the market hands a non-coder proof rather than prose. Build order: rollback id and
files/diff first (both already exist internally — undo checkpoints and the staged-diff data), then
tests/time/tokens (the run already measures them), then perf/bundle delta (needs a build-metrics probe).

**C · The competitor to track is GitHub Spark, not Cursor.**
Cursor, Windsurf, Bolt, Lovable, v0, Replit and Antigravity all sell to people who already write code.
**Spark targets non-programmers — the same person ATOMIC Studio is built for.** It is the only one whose
success directly contests our founding use case, and it carries GitHub's distribution. Treat it as the
benchmark to study continuously; the others are secondary.

## 1. What people hate about competitors → our wedge
Researched July 2026 (Cursor, Windsurf, Replit, Bolt.new, v0, Lovable). Each top complaint = a feature we
turn into a selling point.

| Competitor pain (real, sourced) | ATOMIC Studio answer |
|---|---|
| **Credit/quota anxiety** — Cursor users "run out after a few prompts", Windsurf quotas evaporate + opaque %, Bolt token limits kill builds mid-way | **Zero metering.** Runs on Mohamed's own **free Groq hub** + bring-your-own key. No credits, no quotas, no surprise bills. *(biggest wedge)* |
| **Destructive/rogue agents** — Replit deleted a production DB during a code-freeze, fabricated data, lied about it | **Can't hurt you.** Snapshot before every edit, hidden-git undo that never touches your real git, planning-first mode, dev-only sandbox, explicit confirm on anything destructive, no prod-DB access |
| **"AI said done but broke it"** — Cursor edits silently fail / need retries / claim success falsely | **Self-healing auto-fix** (already built) — catches the error and fixes it so a non-coder never sees a stack trace; verify-after-edit |
| **Lock-in / one model / frontend-only** — Lovable→Supabase only, v0 frontend only | **Model freedom + full-stack.** Combine models in workflows (already built), any backend |
| **Blind on large codebases** — sliced context, no semantic index, breaks across files (67% of enterprise) | **Project index** — file tree + symbol/AST map fed to the agent for cross-file awareness |
| **UI churn & clutter** — Cursor "changes the UI every week", hijacks shortcuts | **Calm, stable, non-coder-first** VS Code-familiar layout that doesn't move |
| **No mobile** — only Bolt supports it | **Built-in phone simulators** — iPhone/iPad live frames (done) + real iOS Simulator on Mac |

Sources: eesel/AltexSoft/Arsturn/DevClass/TechCrunch (Cursor); eesel/CloudZero/DEV (Windsurf); Tom's
Hardware/Fortune/IncidentDB (Replit); NxCode/XDA/uxmagic (Bolt/v0/Lovable); Augment Code / DEV (large-codebase context).

## 2. Where Studio is today (foundation to build on)
Already built (Phases 0–6a): live multi-device webview preview; click-to-edit "wow" (Vite); 6 providers
incl. free ATOMIC Hub; self-healing auto-fix; 2-model workflows; hidden-git undo; packaged .app.
**Missing for a real IDE:** file-tree explorer, code editor (Monaco), tab system, integrated terminal,
generic file read/write, an AI *agent* chat panel, and framework coverage beyond Vite for click-to-edit.

## 3. Phased plan (each phase ships something usable)

### Phase 7 — IDE shell: left file tree + code editor + tabs  ✅ DONE 2026-07-06
- Left sidebar **file/folder explorer** (VS Code-style): expand/collapse, open, create, rename, delete;
  respects `.gitignore`; watches for external changes.
- Center **Monaco editor** (the actual VS Code editor engine) with a **tab bar** for open files; syntax
  highlighting, find/replace, unsaved-dot.
- New generic **file IPC** (`readFile`/`writeFile`/`listDir`/`createFile`/`rename`/`delete`) — today only
  the AI-edit path writes files.
- Every manual save still snapshots for undo (same safety spine).

### Phase 8 — Preview tabs + phone simulators  ✅ DONE 2026-07-06
- **Tabbed preview** area: each running page/app = its own tab; switch, close, reopen.
- Per-tab **device mode**: Desktop / iPhone / iPad responsive frames (extend current `DeviceFrame`).
- **Real iOS Simulator** on Mac via `xcrun simctl` (boot → install Expo/RN build → MJPEG stream +
  tap/swipe forwarding) for true native preview, not just a responsive web frame.
- Web preview and app preview visible side by side.

### Phase 9 — More frameworks (click-to-edit everywhere)
- Extend inspector stamping beyond Vite: **Next.js** (SWC/babel), **Vue** (SFC), **Svelte** (preprocess),
  **Expo/React Native**, so "click element → describe → AI edits" works on all of Mohamed's projects.
- Harden dev-server detection; built-in static server for plain HTML projects.

### Phase 10 — Built-in AI agent (the actual terminal replacement)
- **Agent/chat panel**: multi-file edits, run commands, read the project index, plan → show diffs →
  apply. This is what lets Mohamed stop using the Claude terminal.
- **Integrated terminal** (node-pty) so commands run inside Studio.
- Agent uses the Phase-7 project map for **cross-file awareness** (counters "blind on large codebase").
- **Planning-only mode** + diff approval before writes (counters the Replit trust disaster).

### Phase 11 — Trust & polish
- Global **undo timeline** + snapshots browser, "safe mode", verify-after-edit, non-coder onboarding.

## 4. Suggested build order
Phase 7 first (file tree + editor + tabs = the thing he asked for and the base everything else sits on),
then 8 (preview tabs + simulators), then 9 (frameworks), then 10 (agent). 9 and 8 can overlap.

## 5. Verification per phase
Each phase gets a headless test (like `scripts/test-full-loop.cjs`) plus a 3-step manual GUI checklist,
and a DEVLOG entry. No cloud build credits used (local xcodebuild / simulator only per house rules).
